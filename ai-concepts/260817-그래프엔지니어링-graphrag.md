# 그래프 엔지니어링 (GraphRAG)

> AI 엔지니어링 용어 타임라인 학습 마지막 항목, 2026-08-17

## 용어 헷갈림 정리
"그래프 엔지니어링"은 문맥에 따라 두 가지를 가리킬 수 있다.
1. **지식그래프(Knowledge Graph) 구축** — 이 문서에서 다루는 것, RAG와 결합
2. **LangGraph 같은 에이전트 흐름을 그래프로 설계하는 것** — [멀티에이전트 오케스트레이션](./260817-멀티에이전트-오케스트레이션.md)에서 다룸

## 기존 벡터 RAG의 한계
[RAG 파이프라인](./260807-rag-파이프라인.md)은 질문과 의미적으로 비슷한 청크를 찾아오는 방식이라, **여러 단계를 거쳐야 답이 나오는 질문(multi-hop reasoning)**에 약하다.

> "A 회사를 인수한 B 회사의 CEO는 누구야?"

"A 회사 인수", "B 회사 CEO" 정보가 각각 다른 문서에 흩어져 있으면, 벡터 검색은 의미적으로 비슷한 텍스트 조각만 찾아올 뿐 그 관계를 연결해서 추론하지 못한다.

## 지식그래프로 보완
데이터를 노드(개체)와 엣지(관계)로 구조화해두면 관계 기반 추론이 가능해진다.
```
[A회사] --인수했다--> [B회사] --CEO는--> [김철수]
```
그래프를 따라가면(traversal) "A회사가 인수한 회사의 CEO"라는 질문에 정확히 답할 수 있다.

## GraphRAG 파이프라인 (마이크로소프트, 2024.2)

1. **엔티티/관계 추출**: 문서를 LLM에 넣어 개체와 관계를 자동 추출해 그래프로 구성
2. **커뮤니티 탐지(Community Detection)**: 그래프 안에서 밀접하게 연결된 노드 군집을 찾음
3. **커뮤니티 요약**: 각 군집을 LLM이 미리 요약
4. **검색 시점**: 세부 질문은 그래프 순회로 정밀 답변, 포괄적 질문("전체 요약해줘")은 미리 만든 커뮤니티 요약 활용

## 벡터 RAG vs GraphRAG

| | 벡터 RAG | GraphRAG |
|---|---|---|
| 강점 | 의미적으로 비슷한 내용 찾기 (단일 사실 조회) | 개체 간 관계 추론(multi-hop), 전체 구조 요약 |
| 약점 | 관계 연결 추론 못 함 | 구축 비용 큼(엔티티 추출에 LLM 여러 번 호출), 업데이트 어려움 |
| 적합한 질문 | "이 문서에서 X가 뭐라고 했어?" | "A와 B는 어떤 관계야?", "조직 전체 구조 요약해줘" |

**전부 GraphRAG로 바꾸는 게 정답이 아니라, 관계 추론이 실제로 중요한 도메인에서만 선택적으로 적용하는 게 맞음** — 구축 비용 트레이드오프 때문.

## Neo4j와의 연결
그래프를 실제로 저장하는 게 **그래프 DB(Neo4j 등)**. GraphRAG는 개념/파이프라인이고, Neo4j는 그걸 구현하는 저장소 중 하나.

## 면접 답변 요약
"GraphRAG는 문서에서 개체와 관계를 추출해 지식그래프로 구성하고 기존 벡터 검색과 결합하는 방법입니다. 벡터 검색이 단일 사실 조회에는 강하지만 여러 단계를 거치는 관계 추론에는 약한 한계를, 그래프 순회로 보완합니다. 다만 그래프 구축 자체에 LLM 호출 비용이 크게 들어서, 관계 추론이 중요한 도메인에서만 선택적으로 적용하는 게 맞다고 생각합니다."
