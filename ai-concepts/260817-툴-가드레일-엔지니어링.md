# 툴 엔지니어링 & 가드레일 엔지니어링

> AI 엔지니어링 용어 타임라인 학습 중 정리, 2026-08-17

## 툴 엔지니어링 (Tool Engineering)

### 정의
LLM 에이전트가 실제 세계와 상호작용하도록 **도구(함수)를 정의하고, 모델이 정확히 이해하고 잘 골라 쓰게 설계하는 일**. 모델은 텍스트만 생성하므로, "이런 함수가 있다"는 명세(스키마)를 주고 모델이 알맞게 호출하도록 만드는 게 핵심.

프롬프트 엔지니어링이 "말을 어떻게 할지"라면, 툴 엔지니어링은 "모델이 쓸 수 있는 행동 목록 자체를 어떻게 설계할지".

### 핵심 설계 원칙

1. **이름/설명(description) 명확화**: 모델은 코드를 안 보고 설명 텍스트만 보고 도구를 고름. 설명이 부실하면 오작동.
2. **파라미터 스키마 제한**: `enum` 등으로 값 범위를 명시하지 않으면 모델이 제멋대로 값을 채움.
3. **도구 개수/컨텍스트 비용 관리**: 도구 스키마 자체가 매 턴 컨텍스트 토큰을 소모함 → 필요한 도구만 노출하거나 지연 로딩(이 세션의 `ToolSearch`로 필요할 때만 스키마를 불러오는 방식이 실물 예시).
4. **실행 결과 포맷 설계**: 에러를 모델이 다음 행동을 판단할 수 있는 형태로 정리해서 반환.

### MCP와의 연결
MCP 서버는 "도구 정의 묶음을 표준 프로토콜로 노출하는 것" — MCP 서버를 직접 만든다는 건 곧 툴 엔지니어링을 실제로 해보는 것과 같음.

## 가드레일 엔지니어링 (Guardrail Engineering)

### 정의
에이전트가 의도치 않은/위험한 행동을 하지 못하게 막는 안전장치를 설계하는 일. [방화벽/NGFW](../cs-study/network/260816-네트워크-기초-면접정리.md)의 AI 버전 — "AI 에이전트 경계에 세워두는 문지기".

### 왜 필요한가
LLM은 확률적으로 다음 토큰을 예측하는 모델이라 100% 통제 불가 — 프롬프트 인젝션, 할루시네이션, 위험한 도구 호출(삭제/배포), 민감정보 노출 등. [Agent-Native SRE](./260817-agent-native-sre-self-healing.md)에서 언급한 "AI가 오판해서 위험한 조치를 자동 실행하면 장애를 키운다"는 문제와 직결.

### 가드레일 종류 (어디에 세우느냐)

1. **Input Guardrail**: 입력이 모델에 들어가기 전 필터링 (프롬프트 인젝션 탐지, 민감정보 감지)
2. **Output Guardrail**: 모델 출력이 사용자에게 나가기 전 검증 (유해 콘텐츠, PII 마스킹)
3. **Action/Permission Guardrail**: 도구를 실제로 실행하기 전 막는 계층 — 위험도별 승인 요구, 스코프 제한, rate limiting
4. **Structural Guardrail**: 코드 레벨에서 물리적으로 강제 — 프롬프트 텍스트는 컨텍스트가 길어지면 무시될 수 있어서, 진짜 안전한 가드레일은 이 계층

### 핵심 구분 — "무엇을 겨냥하는가" vs "어떻게 강제하는가"

CLAUDE.md 같은 지침 파일에 "다른 서비스 접근 금지"를 넣는 것은:
- **대상 기준**: 행동(Action) 단계를 겨냥한 것 맞음
- **강제 방식 기준**: 텍스트로 부탁한 것뿐 — **약한 가드레일**

```
CLAUDE.md 지침만              = 행동 단계 겨냥 O, 강제력 X (약한 가드레일)
CLAUDE.md 지침 + Hook/권한체크 = 행동 단계 겨냥 O, 강제력 O (진짜 가드레일)
```

**사례**: 5인 MSA 팀 프로젝트에서 "서비스 경계 침범 금지" 지침을 CLAUDE.md에 넣었는데도 3번 반복된 경우 — 지침이 여러 곳에 분산돼 있었고, 자동 검증 훅 없이 텍스트로만 강제하고 있었던 게 원인. 지침 통합 후 재발은 안 했지만, 근본적으로는 자동 검증 장치가 필요하다는 결론.

### Hook = 하네스가 담당하는 구조적 가드레일

**Hook을 읽고 실행하는 것은 모델이 아니라 하네스(런타임 코드) 자체가 하는 일**이다.

```
하네스(Harness)
├── 시스템 프롬프트   ← 모델이 "읽고 이해해서" 따르는 것 (텍스트, 약한 강제)
├── 도구 실행 루프
├── 권한 체크        ← settings.json/훅이 여기 속함 (코드, 강한 강제)
└── 메모리 시스템
```

모델은 "이 도구를 부르고 싶다"고 요청할 뿐이고, 그 요청을 실제로 실행시킬지는 **모델 바깥의 하네스 코드**가 결정한다. 모델이 지침을 깜빡해도 훅은 모델의 "의지"가 개입할 지점 자체가 없어 절대 뚫리지 않는다.

### Claude Code에서 훅 설정하는 법

**위치**: `.claude/settings.json` (프로젝트, git 공유) / `.claude/settings.local.json` (프로젝트+개인, git 비공유) / `~/.claude/settings.json` (전역). 프로젝트에 `.claude/` 디렉토리가 없으면 직접 만들어야 함 (`mkdir -p .claude`).

**이벤트 종류**:
| 이벤트 | 시점 |
|---|---|
| PreToolUse | 도구 실행 직전 — 여기서 막아야 진짜 차단됨 |
| PostToolUse | 도구 실행 직후 — 결과 검사/로깅용 |
| UserPromptSubmit | 사용자 메시지 제출 시 |
| Stop | 응답 종료 시 |

**예시** — "서비스 경계 침범 금지"를 훅으로 강제:
```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [{ "type": "command", "command": "./.claude/hooks/check-service-boundary.sh" }]
      }
    ]
  }
}
```
```bash
#!/bin/bash
INPUT=$(cat)
FILE_PATH=$(echo "$INPUT" | jq -r '.tool_input.file_path // empty')
if [[ "$FILE_PATH" == *"/other-service/"* ]]; then
  echo '{"decision": "block", "reason": "다른 서비스 경계 침범 금지"}'
  exit 0
fi
exit 0
```
스크립트는 stdin으로 도구 호출 JSON을 받고, exit code/JSON 응답으로 통과·차단을 결정한다.
