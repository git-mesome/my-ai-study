# VLAN · 트렁크 · 주소 객체

> 보안 회사 수습 기간 — 사내 문서 위키 온보딩 자료 학습, 2026-09-16 (방화벽 벤더: FortiGate-50E)

## VLAN(Virtual LAN)이란

하나의 물리 스위치를 논리적으로 여러 **브로드캐스트 도메인**으로 분할하는 기능.

- **문제 상황**: 스위치 한 대에 여러 팀 PC가 다 꽂혀있으면 기본적으로 같은 네트워크로 취급됨 — 서로 브로드캐스트(ARP 등)가 다 들리고, 같은 서브넷이라 IP로 직접 통신도 가능. 팀 간 격리가 안 됨.
- **해결**: 스위치를 물리적으로 나누지 않고, **설정만으로** "1~10번 포트는 VLAN 10(개발팀), 11~20번 포트는 VLAN 20(재무팀)"처럼 가상의 벽을 세움. 물리적으로는 한 스위치, 논리적으로는 서로 다른 네트워크.

### 스위치 vs 공유기(가정용)

- 가정용 공유기는 스위치 기능 + 라우터(NAT) 기능 + WiFi AP 기능이 **한 박스에 다 합쳐진** 것.
- 엔터프라이즈 환경은 이게 분리돼 있음: 통신실 랙에 포트 24~48개짜리 **전용 스위치**가 있고, 각 자리 랜선이 벽을 타고 그 스위치의 실제 물리 포트에 꽂혀있음. VLAN 설정("1~10번 포트")은 이 실제 포트 번호를 가리키는 것.

## access 포트 vs trunk 포트

| | 용도 | VLAN 개수 | 태그 |
|---|---|---|---|
| access 포트 | PC/프린터 등 단말 연결 | 딱 1개로 고정 | 태그 없음 |
| trunk 포트 | 스위치-스위치, 스위치-라우터 연결 (업링크) | 여러 개 동시에 | 802.1Q 태그로 VLAN 구분 |

- **802.1Q 태그**: trunk 링크로 여러 VLAN 트래픽이 한 케이블에 섞여 지나갈 때, 프레임마다 "나는 VLAN 10 소속"이라는 꼬리표를 붙여서 반대쪽 스위치가 원래 VLAN으로 분류할 수 있게 함.
- **주의**: trunk 포트가 "VLAN 10과 VLAN 20을 연결"하는 게 아니라 **스위치와 스위치를 연결**하는 것. 두 VLAN의 트래픽이 그 케이블 하나를 나눠 쓸 뿐, VLAN끼리는 여전히 격리된 상태.

### 스위치 간 물리 연결

케이블 자체는 access와 동일한 평범한 이더넷 케이블. 차이는 **설정** — 연결되는 양쪽 스위치의 포트를 **둘 다** trunk 모드로 맞춰야 함(한쪽만 trunk면 access 쪽이 태그 붙은 프레임을 이해 못 해 버림).

```
# 3층 스위치, 24번 포트 (4층 스위치로 가는 업링크)
interface GigabitEthernet0/24
 switchport mode trunk
 switchport trunk allowed vlan 10,20
```

## VLAN 간 통신 — 왜 L3(라우터/방화벽)를 거쳐야 하나

VLAN마다 보통 IP 서브넷도 다름(예: VLAN10 = `10.0.10.0/24`, VLAN20 = `10.0.20.0/24`). 스위치는 L2 장비라 MAC 기반으로 같은 VLAN 안에서만 프레임을 나름 — 다른 서브넷으로 못 감. 그래서 VLAN을 넘어가려면 IP 라우팅(L3)이 필요함.

### 방법 1 — router-on-a-stick

라우터 한 대를 스위치에 trunk 링크 하나로 연결하고, 물리 인터페이스를 VLAN별 **서브인터페이스**로 쪼개 각각 게이트웨이 IP를 부여.

```
interface GigabitEthernet0/0.10
 encapsulation dot1Q 10
 ip address 10.0.10.1 255.255.255.0   ← VLAN10 게이트웨이

interface GigabitEthernet0/0.20
 encapsulation dot1Q 20
 ip address 10.0.20.1 255.255.255.0   ← VLAN20 게이트웨이
```

단점: trunk 케이블 하나의 대역폭을 VLAN 간 트래픽이 나눠 써야 해서 병목 발생 가능.

### 방법 2 — L3 스위치 (요즘 실무 표준)

스위치 자체가 라우팅 기능을 겸함. VLAN마다 **SVI(Switched Virtual Interface)**라는 가상 인터페이스를 만들어 게이트웨이 역할을 하게 하고, 스위치 내부 칩에서 바로 라우팅 — 외부로 안 나가서 router-on-a-stick보다 빠름.

```
interface Vlan10
 ip address 10.0.10.1 255.255.255.0

interface Vlan20
 ip address 10.0.20.1 255.255.255.0
```

### 보안 관점 — 세그멘테이션이 "실제로 구현되는" 지점

이 SVI(또는 router-on-a-stick의 라우터)가 바로 VLAN 간 통신의 L3 경계. 실무에서는 이 경계에 **ACL·방화벽 정책**을 걸어 "VLAN10은 VLAN20의 특정 포트만 접근 가능" 같은 통제를 함. VLAN만 나누고 이 경계에 정책을 안 걸면 사실상 자유롭게 라우팅돼서 VLAN 분리(격리)의 의미가 없어짐.

## 주소 객체(Address Object)

방화벽 정책을 만들 때마다 IP를 직접 입력하지 않고, **IP/대역에 이름을 붙여 재사용**하는 것.

- **왜 쓰나**: 규칙 여러 개가 같은 IP(예: 개발서버 `10.0.10.5`)를 참조할 때, IP가 바뀌면 그 규칙들을 일일이 다 찾아 고쳐야 함. 대신 이름 붙은 객체(`DEV-SERVER-01`)로 참조해두면, 객체 하나만 수정해도 그 객체를 쓰는 규칙 전체에 자동 반영됨.
- **비유**: 코드에서 하드코딩 대신 상수(`private static final String DEV_SERVER = "10.0.10.5"`)를 쓰는 것과 같은 원리 — 이름 하나만 바꾸면 쓰는 곳 전부 반영.
- **담는 형태**: 단일 IP, 서브넷(`10.0.10.0/24`), IP 범위, (벤더에 따라) FQDN 도메인. 여러 객체를 묶은 **주소 그룹(Address Group)**도 있음.

### FortiGate-50E 기준 용어/위치

- GUI: **Policy & Objects → Addresses**
- CLI: `config firewall address` (그룹은 `config firewall addrgrp`)
- 지원 타입: Subnet, IP Range, FQDN, Wildcard FQDN, Geography(국가) 등
- 정책(Policy) 생성 시 Source/Destination에 IP 대신 이 Address 객체를 선택해서 참조.
