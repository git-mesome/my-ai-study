# 메모리 엔지니어링 (Memory Engineering)

> AI 엔지니어링 용어 타임라인 학습 중 정리, 2026-08-17

## 정의
에이전트가 **세션 안/세션 간 정보를 어떻게 저장하고, 언제 다시 불러올지**를 설계하는 일.

## 왜 컨텍스트 엔지니어링만으론 부족한가
[컨텍스트 엔지니어링](./260807-하네스-컨텍스트엔지니어링.md)은 "이번 턴에 뭘 넣을지"의 문제였지만, 컨텍스트 윈도우는 세션이 끝나면 사라진다. 메모리 엔지니어링은 **"세션 하나가 끝나도, 다음 세션에서 필요한 정보를 어떻게 유지시킬 것인가"**를 다룬다.

## 메모리의 종류 (기간 기준)

| 종류 | 범위 | 예시 |
|---|---|---|
| 단기 기억(Short-term) | 지금 세션 안에서만 | 대화 히스토리, 이번 턴에 읽은 파일 |
| 장기 기억(Long-term) | 세션을 넘어 영구 유지 | 사용자 선호, 과거 결정 사항 |
| 절차 기억(Procedural) | "어떻게 할지"에 대한 학습 | 반복된 실수에서 배운 규칙 (CLAUDE.md 축적과 유사) |

## 핵심 설계 문제 3가지
1. **뭘 저장할지(선택)**: 대화 전체가 아니라 나중에 쓸모 있는 요약된 사실만 추출
2. **어떻게 불러올지(검색)**: 인덱스 상시 로드 + 필요시 세부 조회, 또는 벡터 검색(RAG 방식)
3. **언제 갱신/삭제할지**: 오래된/틀린 정보를 최신으로 덮어쓰거나 정정

## MemGPT (2023.10, 이 분야를 촉발한 논문)
메모리를 OS의 메모리 계층에 비유:
```
컨텍스트 윈도우(RAM, 빠르지만 작음) ←→ 외부 저장소(디스크, 느리지만 큼)
```
컨텍스트가 꽉 차면 오래된 정보를 "디스크"(벡터DB/파일)로 내보내고, 필요할 때 다시 "RAM"(컨텍스트)으로 불러온다. 지금 실무 장기 기억 에이전트 설계 대부분의 원형.

## 세션 삭제 vs 메모리 삭제는 별개
```
세션(대화)             = RAM (컨텍스트 윈도우, 세션 끝나면 사라짐)
memory/ 디렉토리 파일들 = 디스크 (파일시스템에 저장, 세션 생명주기와 무관)
```
`/clear`나 세션 종료는 RAM만 비우는 것 — 디스크에 저장된 메모리 파일은 그대로 남는다. 메모리를 지우려면 명시적으로 삭제를 요청하거나 파일을 직접 지워야 한다.

## 정리(청소)는 언제 하나
자동 만료(TTL)가 기본으로 있는 게 아니라, 실무에서 쓰는 정리 전략은 캐시 무효화 전략과 동일한 선상에 있다.

| 전략 | 방식 | 캐시로 치면 |
|---|---|---|
| TTL(Time-To-Live) | 일정 기간 지나면 자동 만료 | Redis `EXPIRE` |
| LRU | 오래 안 쓰인 메모리부터 삭제 | LRU 캐시 |
| 중요도 기반 유지 | 자주 참조되거나 명시적으로 중요 표시된 것만 남김 | 우선순위 큐 |
| 주기적 요약/압축(Consolidation) | 비슷한 메모리 여러 개를 하나로 병합 | 로그 압축, 파티션 롤업 |
| 명시적 삭제 명령 | 사용자가 "잊어줘" 하면 그때 지움 | 캐시 무효화 |

## 실무 연결 — 이 레포의 memory 시스템
Claude Code의 `memory/` 구조가 실물 예시:
```
MEMORY.md      ← 매 세션 상시 로드되는 "인덱스" (짧은 요약)
feedback_*.md   ← 관련 있어 보일 때만 Read로 불러오는 상세 내용
project_*.md
```
- **선택**: 회사 실명/개인 서사는 저장 안 하고 학습 키워드만 추출하는 판단이 "뭘 저장할지" 설계
- **검색**: 인덱스는 상시 로드, 나머지는 관련성 판단 후 선택적 Read
- **갱신**: 중복 발견 시 새로 안 만들고 기존 파일 수정, 틀린 메모리는 발견 즉시 삭제 — 다만 **정기 스케줄이 아니라 "쓰다가 발견하면 그때그때 치우는" lazy 방식**이라 오래된 프로젝트 메모리가 계속 누적될 수 있는 구조

## Auto Memory (Claude Code 기능, 2026.2 출시)
이 메모리 시스템 자체는 **모델(Claude)의 능력이 아니라 하네스(Claude Code)의 기능**. `/memory` 폴더를 세션 시작 시점에 자동으로 읽고, 대화 중 스스로 판단해서 씀. 2023~2024년에 MemGPT 논문, LangChain Memory 모듈, 벡터DB 기반 자체 구현, Mem0 같은 서드파티 라이브러리로 커뮤니티가 먼저 메워온 공백을, Anthropic이 2026년에 네이티브 기능으로 흡수한 것.

## 면접 답변 요약
"메모리 엔지니어링은 에이전트가 세션을 넘어 정보를 유지하도록 무엇을 저장하고, 언제 다시 불러오고, 어떻게 갱신·삭제할지 설계하는 일입니다. MemGPT의 OS 메모리 계층 비유처럼 컨텍스트 윈도우를 RAM, 벡터DB나 파일을 디스크로 보는 구조가 일반적이고, 캐시 무효화 전략(TTL, LRU, 중요도 기반)을 메모리 정리에도 적용해야 합니다."
