# 하네스(Harness) & 컨텍스트 엔지니어링

> Claude Code를 쓰면서 시스템 프롬프트 이야기가 나올 때 접한 용어, 2026-08-07

## 하네스란

LLM 모델(말)을 감싸서 실제로 동작하게 만드는 소프트웨어 전체(안장/고삐).

모델 혼자서는 파일을 읽거나 코드를 실행할 수 없다. 하네스가 그 주변을 감싸서:

- 시스템 프롬프트 (규칙, 페르소나, 금기사항)
- 도구(tool) 정의와 실행 루프 — "모델 호출 → 도구 실행 → 결과 다시 모델에 넣기" 반복
- 권한 체크 (예: 위험한 명령 실행 전 사용자 승인)
- 메모리 시스템 (세션 간 기억 유지)

를 담당한다. Claude Code 자체가 하나의 하네스다.

## 컨텍스트 엔지니어링이란

하네스가 하는 여러 일 중 하나. **한정된 컨텍스트 윈도우 안에 이번 턴에 모델한테 정확히 뭘 넣어줄지 설계하는 일.**

하네스가 상위 개념, 컨텍스트 엔지니어링은 그 안의 구체적인 역할 하나 (비유: 하네스 = 자동차 전체, 컨텍스트 엔지니어링 = 연료 분사 시스템).

### 언제 필요한가

- 대화가 길어져 컨텍스트 윈도우 한계에 닿을 때
- 파일을 수십 개 읽거나 도구 결과가 방대한 작업을 할 때 (다 넣으면 낭비 + 한계 초과)
- 여러 세션에 걸친 기억이 필요할 때

## 압축 기법

1. **슬라이딩 윈도우 (Sliding Window)** — 최근 N개 메시지만 유지, 오래된 건 그냥 잘라냄. 단순하지만 초반에 정한 규칙 같은 맥락이 유실될 위험 있음
2. **요약 압축 (Summarization / Compaction)** — 오래된 메시지들을 LLM한테 요약시켜서 원본 대신 요약본으로 치환. Claude Code가 실제로 이 방식을 씀 (컨텍스트 한계 근접 시 자동 compaction)
3. **도구 결과 절삭 (Tool Output Truncation)** — 파일 전체나 방대한 검색 결과 대신 앞부분/관련 부분만 남기고 나머지는 버림 (예: Read 도구의 기본 2000줄 제한)
4. **외부 저장 + 선택적 불러오기 (Offload + Retrieval)** — 압축이 아니라 컨텍스트 밖으로 아예 빼는 방식. 전체는 파일/DB에 저장해두고 필요할 때만 검색해서 그 조각만 다시 넣음

실무에서는 보통 네 가지를 섞어 씀: 최근 대화는 슬라이딩 윈도우로 두고, 넘치면 요약하고, 도구 결과는 절삭하고, 오래된 건 파일로 offload.

### 최소 예제 (의사코드)

```python
MAX_TOKENS = 100_000

def add_message(history, new_msg):
    history.append(new_msg)
    if count_tokens(history) > MAX_TOKENS:
        old = history[:-10]          # 최근 10개는 남기고
        summary = llm_summarize(old) # 나머지는 요약
        history = [summary] + history[-10:]
    return history
```

## 실무 연결

- 이 레포의 `memory/MEMORY.md` 구조가 offload + retrieval의 실제 사례: 매 세션마다 대화 전체를 넣는 대신, 필요한 요약만 파일로 저장 → 인덱스(`MEMORY.md`)만 상시 로드 → 관련 있을 때만 세부 파일 Read
- RAG도 같은 원리: 문서 전체를 프롬프트에 넣는 대신 검색으로 관련된 조각만 뽑아 컨텍스트에 넣음
