# 루프 엔지니어링 (Loop Engineering)

> AI 관련 자료 찾아보다가 발견한 용어, 2026-08-07

## 정의

에이전트의 "모델 호출 → 행동 → 관찰 → 다시 모델 호출" 반복 루프를 안전하고 목적에 맞게 멈추도록 설계하는 일. 그냥 반복문 코드가 아니라, **언제/어떻게 멈출지**를 설계하는 게 핵심.

[하네스](./260807-하네스-컨텍스트엔지니어링.md)가 담당하는 "도구 실행 루프"를 더 안전하게 만드는 하위 분야로 볼 수 있다.

## 왜 필요한가

루프를 그냥 두면 생기는 문제:

- **무한 루프**: 종료 조건이 없으면 태스크가 끝났는지 모델 스스로도 판단 못 하고 영원히 도구만 호출
- **같은 실수 반복**: 에러가 나면 재시도하는데, 같은 방식으로만 재시도하면 똑같이 실패 → "멈춰있는(stuck) 상태"를 감지 못하면 토큰/시간만 태움

## 다루는 요소들

1. **종료 조건 (termination)** — 태스크 완료 판단, 최대 반복 횟수, 토큰/시간 예산 캡
2. **진행 감지 (stuck detection)** — 같은 행동을 반복하거나 결과가 안 바뀌면 "멈춰있다"고 판단해서 다른 전략 시도 또는 중단
3. **검증 단계 (verification)** — 매 스텝마다 맹목적으로 다음으로 안 넘어가고, 결과가 맞는지 확인 후 진행 (예: 코드 수정 후 테스트 실행)
4. **재시도 전략** — 일시적 에러는 백오프하며 재시도, 근본적 에러는 다른 방법 시도 또는 포기
5. **사람 개입 지점 (human-in-the-loop)** — 계속 막히면 무한정 시도하지 말고 사용자에게 물어보기

## 최소 예제 (의사코드)

```python
MAX_ITERATIONS = 20

def agent_loop(task):
    history = []
    last_action = None
    stuck_count = 0

    for i in range(MAX_ITERATIONS):
        action = call_model(task, history)

        if action == last_action:          # 같은 행동 반복 감지
            stuck_count += 1
            if stuck_count >= 3:
                return ask_human("계속 같은 시도만 반복돼, 도와줘")
        else:
            stuck_count = 0

        result = execute(action)
        history.append((action, result))
        last_action = action

        if is_task_complete(result):       # 종료 조건
            return result

    return "최대 반복 횟수 초과, 중단"
```

## 실무 연결

- Claude Code의 `Workflow` 도구에 있는 "loop-until-dry" 패턴이 실제 사례: 연속 K번 새로운 결과가 안 나오면(진행 감지 실패) 중단
- 예산 기반 종료: `budget.total`이 설정되면 `budget.remaining() > threshold`일 때만 루프 계속 — 토큰 예산 캡의 실제 구현
- ReAct(Reason-Act-Observe) 패턴도 이 루프 구조 — Reason(모델 판단) → Act(도구 실행) → Observe(결과 반영) 반복
